# RFC-0003 Feedback and Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keypad plays its own key sounds and a chosen haptic pattern. Every setting (enabled state, shortcut, active area, stay open, feedback) persists and can be changed in a Settings window that opens from the Dock, the Dock menu and ⌘,.

**Architecture:**
- **Core:** the settings value types, their validation, pure editing helpers and the protocols for the services they need.
- **System:** adapters that store the settings, register the hotkey, name keys, manage the login item and play feedback.
- **UI:** an observable `SettingsModel` that coordinates them, and the SwiftUI tabs inside an AppKit Settings window.
- **App target:** wires settings changes into the running session and feedback player.

**Tech Stack:** Swift 6, SwiftPM 6.2, Swift Testing, SwiftUI `Form` (grouped), AppKit (`NSTabViewController`, `NSDockTile`, `NSSound`, `NSHapticFeedbackManager`, `NSEvent` local monitors), Carbon (`RegisterEventHotKey`, `UCKeyTranslate`), ServiceManagement (`SMAppService`), `UserDefaults` + `JSONEncoder`.

**Spec:** `docs/rfcs/0003-feedback-and-settings.md` (foundation: `docs/rfcs/0000-vision-and-architecture.md` §7 F1–F11; shipped session: `docs/rfcs/0002-keypad-session.md`)

## Global Constraints

- **Git:**
  - Branch `feature/feedback-and-settings`, from `develop`; merge into `develop` with `--no-ff`.
  - Never push without the PM's OK.
  - Conventional Commits, made with the repo-local identity, ending with the harness's `Co-Authored-By` trailer.
  - Stage files by path; never `git add -A`.
- **Modules:**
  - `KeypadCore` imports Foundation and `os` only.
  - `KeypadSystem` and `KeypadUI` never import each other; KeypadUI may import AppKit.
  - The app target only wires things together.
- **Swift:** Swift 6, warnings are errors. Protocols and adapters for system services are `@MainActor`. Core value types are `Sendable`.
- **Defaults:**
  - Enabled on; shortcut ⌃⌥K; active area the whole surface; stay open after typing on.
  - Haptics on with **Standard**; key sound on with **Wood**.
  - Open at login is never stored and is off until the user turns it on.
- **Shortcut rule:** valid when the key is F1–F20 (any modifiers), or when it has **at least two of ⌘ ⌃ ⌥ ⇧, one of them ⌘ or ⌃**. Modifier keys alone are invalid. `.function`, `.numericPad` and `.capsLock` flags are ignored.
- **Active area:** at least **0.2** of the width and height, always inside `0...1`. VoiceOver steps are **0.05**.
- **Haptic mapping:** Standard → `.generic`, Light → `.alignment`, Pronounced → `.levelChange`, performed with `performanceTime: .now`.
- **Sounds:**
  - `wood`, `soft`, `deep`, `crisp`, generated by `swift Tools/KeySounds/generate.swift <dir>`.
  - Ship the four non-demo `.wav` files unchanged: 48 kHz, mono, 16-bit.
  - The sound plays on `.keyAccepted` and may cut the previous sound short.
- **Persistence:** one `UserDefaults` entry, key `"settings"`, holding JSON `{"version": 1, "settings": {…}}`. Anything unreadable falls back to defaults, field by field.
- **Strings:**
  - Copy every key and its English and Turkish values verbatim from RFC-0003 §Strings, plus `settings.activeArea.accessibilityValue`: en "Width %1$lld%%, height %2$lld%%", tr "Genişlik %%%1$lld, yükseklik %%%2$lld".

  - Remove `settings.placeholder`.
- **Logging:** `Logger(subsystem: "io.berkan.keypad", category:)`. Never log digits, buffer contents or key codes; a shortcut is never logged.
- **Platform:**
  - Public API only: no `showSettingsWindow:` selector.
  - No third-party packages.
  - No new entitlements (`SMAppService.mainApp` needs none).
- **Commands (AGENTS.md §10):**
  - Format: `swift format format --in-place --recursive Packages Keypad`.
  - Lint must print nothing: `swift format lint --recursive --strict Packages Keypad`.
  - Tests: `swift test --package-path Packages/KeypadKit`.

## Review Focus

1. **Recording the current shortcut opens a session.** While the recorder is active, the hotkey must be unregistered — `recordingSuspendsTheShortcut` in Task 7.
2. **A refused shortcut leaves Keypad without one.** When macOS refuses a new shortcut, the previous one is registered again and kept — `refusedCandidateKeepsThePreviousShortcut` in Task 7.
3. **Corrupt or old stored settings crash or reset everything.** Garbage data gives the defaults. A wrong field type or an unknown enum value resets only that field — `garbageDataLoadsDefaults` in Task 4, `invalidFieldsFallBackOneByOne` in Task 2.
4. **An impossible active area.** NaN, negative, oversized or off-surface values, and drags past the edge, still give an area inside the trackpad and at least 20 % in size — `nonFiniteValuesGiveTheWholeSurface` and `draggingPastTheEdgeStopsAtIt` in Task 1.
5. **The disabled state doesn't survive a relaunch.** A saved disabled state must not register the shortcut at launch — `startDoesNotRegisterWhenDisabled` in Task 7.

- Produces: `@MainActor @Observable public final class SettingsModel`, with:
  - `public init(store: SettingsStore, hotkey: HotkeyRegistrar, loginItem: LoginItemController, feedback: FeedbackPreview, shortcutNames: ShortcutNaming)`.
  - State: `public private(set) var settings: KeypadSettings` (loaded in `init`), `public private(set) var recorder: ShortcutRecorderState`, `public private(set) var isSavedShortcutRefused: Bool`, `public private(set) var loginItemStatus: LoginItemStatus`.

  - Lifecycle: `public func start()`.
  - Setters: `setEnabled(_:)`, `setStaysOpenAfterTyping(_:)`, `setActiveArea(_:)`, `setHapticsOn(_:)`, `setHapticPattern(_:)`, `setSoundOn(_:)`, `setSound(_:)`.

  - Login item: `setOpenAtLogin(_:)`, `refreshLoginItemStatus()`, `openLoginItems()`.
  - Names: `public var shortcutName: String`.
- Rules:
  - Every successful change saves through the store, then calls `onChange`.
  - `start()` registers the saved shortcut only when enabled, and sets `isSavedShortcutRefused` from the result.
  - `setEnabled` registers or unregisters.
  - The pattern and sound setters call `feedback.preview`.
  - **`startRecording`** unregisters.
  - **`record`:**
    - An invalid candidate gives `.invalid`.
    - A valid candidate is registered; if Keypad is disabled, it is unregistered again right after the check.
      - On success it is saved, `recorder` becomes `.idle`, and `isSavedShortcutRefused` becomes false.
      - On failure the old shortcut is registered again if Keypad is enabled, and `recorder` becomes `.refused`.
  - **`cancelRecording`** registers the old shortcut again if Keypad is enabled.
  - **`resetShortcut`** is `record(.default)`.
  - **`setOpenAtLogin`** calls `loginItem.setEnabled` and then refreshes the status. An error leaves the status unchanged.
